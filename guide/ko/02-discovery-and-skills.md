# 2. 발견과 사용 지식

## 도구 이름과 도움말

도구 이름만 입력한 호출은 `--help`와 같은 도움말을 제공한다.

```sh
tool
tool --help
```

명령군도 같은 방식으로 탐색한다.

```sh
tool deploy
tool deploy --help
```

`tool deploy`는 배포 관련 명령을 보여준다. 명령군에는 암묵적 실행이 없다. 명령군을 살펴보는 호출에서 배포가 시작되거나 객체가 생성되지는 않는다.

실행 명령은 명령군과 구분한다. `tool status`처럼 필요한 입력이 모두 정해져 있는 명령은 추가 인자 없이 실행할 수 있다. 필수 입력이 빠진 실행 명령은 입력 오류를 반환한다.

작은 도구는 명령을 바로 제공하고, 기능이 많다면 의미 있는 명령군을 둘 수 있다. 구조는 제작자가 정하며, 기능 수가 늘었다는 이유로 기존 명령 경로를 자동 변경하지 않는다.

## 도움말과 사용 스킬

명령의 계약은 기본적으로 도움말에서 확인한다. 호출 방법과 사용에 필요한 입력·결과 정보를 함께 설명한다. 필수적인 호출 정보를 알아내기 위해 별도 스키마를 조회해야 해서는 안 된다.

| 표면 | 주요 내용 |
| --- | --- |
| 도움말 | 명령 설명, 호출 문법, 입력, 필요한 결과 구조, 짧은 예시 |
| 사용 스킬 | 적용 상황, 작업 순서, 결과 해석, 명령 간 관계 |

배포 도구의 도움말에는 `list`, `inspect`, `logs`의 입력이 설명돼 있다. 배포 진단 스킬에는 조사할 배포를 찾고, 실패한 단계를 확인하고, 해당 로그를 읽는 흐름이 들어간다.

도움말에서 스킬을 읽는 경로를 찾을 수 있어야 한다. 정확한 명령 이름은 도구가 정한다. 작은 도구는 하나의 스킬을 제공할 수 있고, 큰 도구는 이름과 적용 상황을 목록으로 보여주고, 필요한 스킬을 선택한 뒤 참조를 따라 상세 내용을 읽을 수 있게 한다.

## 작업에 필요한 정보 읽기

배포 하나를 확인하는 작업에는 전체 명령 트리가 필요하지 않다.

```sh
tool
tool deploy
tool deploy inspect --help
```

이처럼 명령이 여러 단계로 나뉜 도구에서는 최상위 도움말이 다음에 읽을 곳을 고르는 데 필요한 정보를 제공한다. 기능 이름과 적용 상황을 보여주고, 각 명령의 인자와 예제는 상세 도움말에 둔다. 명령을 선택한 뒤에는 입력과 출력의 상세 계약을 읽고, 작업 순서가 필요하면 관련 스킬로 이어진다.

탐색 단계가 많을수록 좋은 것은 아니다. 작은 도구라면 한 번의 도움말로 충분할 수 있다. 기능이 늘어났을 때도 관련 없는 설명을 먼저 읽지 않고 필요한 부분에 도달할 수 있도록 구성한다.

사용 지식에는 각 단계에서 필요한 계약 정보를 함께 넣을 수 있다. 배포 ID를 추출하는 흐름이라면 목록 명령 옆에 해당 목록 필드를 보여주고, 그 ID를 받는 상세 조회 명령으로 연결한다. 전체 도구 명세를 붙이기보다 그 흐름에 필요한 필드를 포함한다. 명령 문법과 필드 설명은 가능한 한 공통 선언에서 가져와, 사용 지식이 별도로 관리하는 복사본이 되지 않게 한다.

별도 전역 schema 명령은 필수가 아니다. 구조화된 계약을 소비하는 연동이 있다면 그 용도의 프로그램 API나 내보내기를 제공할 수 있다. 범위와 형식은 소비하는 쪽의 필요에 맞추며, 일반적인 명령 사용은 도움말로 이해할 수 있어야 한다. 충분한 도움말과 사용 지식에 스키마 조회를 추가하면 에이전트 성능이 향상된다는 근거를 이 가이드가 제시하는 것은 아니다.

도움말과 사용 스킬은 실행되는 버전의 동작을 설명해야 한다. 실행 버전도 조회할 수 있게 한다. 구조화된 계약을 제공한다면 그것도 같은 버전과 일치해야 한다. 같은 버전으로 배포하는 것은 일치를 유지하는 방법이지만, 저술된 예제의 정확성까지 보장하지는 않는다. 재발견이 가능하다는 사실이 호환성의 필요를 없애지도 않는다. 호환성 정책은 도구의 호출자와 배포 방식에 맞춰 정한다.
