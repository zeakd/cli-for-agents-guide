# 2. 발견과 사용 지식

## 이름으로 시작한다

도구 이름만 입력한 호출과 도움말 옵션은 같은 도움말을 제공한다.

```sh
tool
tool --help
```

명령군에도 같은 규칙을 적용한다.

```sh
tool repo
tool repo --help
```

명령군에는 암묵적인 실행 동작이 없다. 탐색이 객체를 생성하거나 애플리케이션을 실행해서는 안 된다. 실행 명령은 다르다. 인자가 필요 없는 명령은 바로 실행할 수 있고, 필수 입력이 빠진 명령은 입력 오류를 알린다. 인자 없는 모든 실행 명령을 도움말로 바꾸지 않는다.

작은 도구는 명령을 바로 보여줄 수 있다. 큰 도구는 의미 있는 명령군을 도입할 수 있다. 불필요한 계층을 피하고, 기능 수가 늘었다는 이유로 기존 명령 경로를 자동 변경하지 않는다. 제작자가 구조를 명시적으로 선택한다.

## 도움말·스킬·스키마

도움말은 사용할 수 있는 명령과 호출 문법을 설명한다. 스키마는 선언된 계약을 구조화된 데이터로 제공한다. 스킬은 도구로 일하는 방법을 가르친다. 언제 유용한지, 명령들이 어떻게 연결되는지, 결과가 무엇을 뜻하는지, 어떤 실수를 피해야 하는지를 담는다.

도움말에서 이 사용 지식을 읽는 진입점을 발견할 수 있어야 한다. 스킬 명령의 정확한 이름은 도구가 정하되, 목적과 접근 경로는 명확해야 한다.

작은 도구는 하나의 스킬로 충분할 수 있다. 큰 도구는 스킬 이름과 적용 상황을 목록으로 제공하고, 하나를 선택한 뒤 더 자세한 참조를 따라갈 수 있게 한다.

```text
도움말 -> 스킬 이름과 읽을 상황 -> 선택한 스킬 -> 상세 참조
```

선언에서 생성한 명령 레퍼런스는 유용하지만 저술된 작업 방법과 안내를 대신하지는 않는다. 반대로 스킬도 현재 도움말이나 스키마로 연결할 수 있다면 모든 기계적 세부사항을 복제할 필요는 없다.

## 설치된 동작을 설명한다

도움말·스킬·스키마는 실행되는 버전을 설명해야 한다. 사용 지식을 CLI와 함께 배포하면 일치를 유지하는 데 도움이 된다. 실행 버전도 확인할 수 있어야 한다.

버전을 맞췄다는 사실만으로 저술된 설명의 정확성이 증명되지는 않는다. 예제와 동작에 관한 주장을 검증한다. 재발견할 수 있다는 사실이 호환성의 필요를 없애지도 않는다. 호환성 정책은 호출자와 배포 방식에 맞춰 도구 제작자가 정한다.
