# 3. 입력과 실행

## 입력을 발견할 수 있게 한다

실행 전에 위치 인자·옵션·허용값·기본값·필수 입력을 설명한다. 파이프를 읽는 명령은 stdin도 포함한다. 호출자는 기대 형식과 필수 여부를 알아야 한다.

다음은 설명을 위한 명령 예시다.

```sh
tool report export sales --format csv
```

보고서 이름을 필수로 받고 `--format`에 `json` 또는 `csv`만 허용할 수 있다. 도움말·스키마·실행은 이 규칙에 동의해야 한다.

## 잘못된 입력을 거절한다

모르는 명령·옵션, 빠진 필수 값, 잘못된 타입·허용값, 선언한 개수를 넘는 위치 인자를 조용히 무시하지 않는다. 요청 일부만 받아들이고 성공이라고 하면 실제로 일어난 일을 잘못 전달한다.

입력 오류는 잘못된 입력과 수정에 필요한 근거를 제공해야 한다.

```text
잘못된 값: --format yaml
허용 값: json, csv
```

가까운 후보를 제안할 수는 있지만 자동으로 대체해 실행하지 않는다. 해당 오류의 설명으로 충분하면 전체 도움말을 덤프하지 않고 관련 사용법만 제공한다. 구조화된 오류 상세를 주면 호출자가 산문에서 허용값을 추출하지 않아도 된다.

## 기본은 비대화형 실행

일반 호출은 예상하지 못한 질문이나 메뉴에서 멈추지 않는다. 필수 입력이 없으면 무엇이 필요한지 설명하고 실패한다. 도구는 대화형 진행을 명시적인 선택으로 제공할 수 있다.

`--human`은 표현을 바꾸며 대화형 동작을 켜지 않는다. 선언된 stdin과 명시적으로 요청한 대기도 예상 밖의 질문과 다르다. 호출자가 선택 전에 그 동작을 발견할 수 있어야 한다.

## 정의를 공유한다

일반적인 인자는 하나의 입력 선언에서 파싱·검증·도움말·스키마를 생성하도록 프레임워크가 지원하는 것이 좋다. 옵션 추가를 여러 곳의 동시 수정 대신 한 번의 변경으로 만든다.

특수한 표현식 문법은 별도 파서가 필요할 수 있다. 이 경우에도 문법을 설명하고 같은 입력·오류 계약을 지켜야 한다. 파서 구현은 선택이고, 설명과 동작의 일치는 요구사항이다.
