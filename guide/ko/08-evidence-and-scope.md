# 8. 근거와 적용 범위

## 요구·방법·사례를 구분한다

“입력 설명과 검증이 일치한다”는 호출자에게 제공하는 계약이다. “둘을 한 선언에서 생성한다”는 구현 방법이다. “임시 홈을 사용한다”는 지속 상태를 소유한 도구의 테스트 패턴이다.

셋을 모두 보편 요구로 다루면 장치가 필요 없는 도구에도 부담을 준다. 권고가 적용되는 상황을 드러내고 다른 선택이 적절한 조건을 설명한다.

필드·명령·규칙을 추가할 때 다음을 묻는다.

- 결과를 해석하거나 행동을 선택하고 구성하는 데 도움이 되는가?
- 흔한 올바른 사용을 더 간단하게 만드는가?
- 유지 과정의 누락이나 모순을 줄이는가?
- 그 이익이 출력량과 구현 비용을 정당화하는가?

## 가정을 정직하게 밝힌다

도구에 익숙하지 않거나 이전 맥락이 부족한 호출자를 위해 설계한다. 모든 AI 호출이 백지 상태라거나 인간의 컨텍스트가 무한하다고 주장할 필요는 없다.

입력 검증·관측 가능한 상태·테스트 가능한 의존성은 AI 이전에도 유용했다. 에이전트에게 유용하다는 사실이 역사적 새로움을 증명하지는 않는다. 성능·정확성 주장은 그에 맞는 근거가 필요하다. 생성된 스키마만으로 모든 핸들러가 이를 따른다고 증명할 수는 없다.

CLI·MCP 등 인터페이스 선택은 환경에 따라 달라진다. 이 가이드는 CLI를 선택했을 때 제공할 표면을 설명한다. 에이전트 하네스·호환성 정책·언어·패키지 매니저를 지정하지 않는다.

## 참조 구현의 지원 범위

[TypeScript 구현](https://github.com/zeakd/cli-for-agents-ts)은 구체적인 사례이며 이 문서의 모든 권고를 이미 구현했다는 뜻은 아니다. 아래 비교는 [리비전 701eb6450a181640e63a47a281a4752cb6644e0c](https://github.com/zeakd/cli-for-agents-ts/tree/701eb6450a181640e63a47a281a4752cb6644e0c)를 기준으로 고정했다. 이후 리비전은 다를 수 있다.

| 영역 | 해당 리비전의 동작 | 이 가이드가 설명하는 계약 |
| --- | --- | --- |
| 발견 | 최상위·도메인 도움말, 생성 guide, schema | 필요한 경우 여러 저술 스킬을 선택적으로 발견하는 기능도 지원 |
| 출력 | --json이 없으면 렌더러 실행; 오류 표현은 TTY에 따라 달라질 수 있음 | 일반 결과는 기본 JSON; 명시적인 --human |
| 오류 채널 | JSON 오류는 stderr | 기본 JSON 성공·실패는 stdout; 목적물 출력 오류는 stderr 유지 |
| 출력 선언 | raw·stream 모드 존재; schema는 입력 설명 | 호출 전에 대체 출력 형식을 발견 가능 |
| 입력 | 선언된 핸들러 입력은 필수 입력·모르는 옵션 검사; 내장 시스템 명령·도움말 경로는 미선언 입력을 무시할 수 있음; 선언된 핸들러도 위치 인자 최대 개수를 강제하지 않음 | 초과 위치 인자를 포함해 선언한 계약 밖의 입력 거절 |
| 명령군 라우팅 | 선택적 fallback이 모르는 verb에서 실행될 수 있음 | 명령군에 암묵적 실행 없음; 잘못된 명령은 실패 |
| 후속 행동 | 오류 복구 필드 존재 | 성공·실패에 관련 행동과 힌트 제공 가능 |
| 사용 지식 | 생성 guide가 doctor 선행과 복구 명령의 직접 실행 권고 | doctor는 선택적; 제안은 허가가 아님 |
| 제작·검증 | 공통 선언과 컨텍스트 주입 | 유용한 구현 방법이며 실제 CLI 경계 검증도 포함 |

이 장들만 보고 패키지가 --human이나 확장된 후속 행동·부분 결과·스킬 계약을 지원한다고 가정해서는 안 된다. 가이드의 `tool` 명령은 설계 예시이며 해당 패키지의 실행 예제가 아니다. 필드명과 정확한 스킬 명령 이름은 구현이 정하며, 동작의 구분이 가이드의 권고다.

해당 구현을 평가할 때는 [고정된 소스](https://github.com/zeakd/cli-for-agents-ts/tree/701eb6450a181640e63a47a281a4752cb6644e0c/src)를 사용한다. 코드가 바뀌면 지원 범위도 버전과 함께 관리한다. 동작을 지원한다고 설명하기 전에 생성된 사실과 저술된 예제를 모두 검증한다.
