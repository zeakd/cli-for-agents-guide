# 5. 상태와 후속 행동

## 결과의 의미를 설명한다

없으면 호출자가 오해할 수 있는 상태·범위·출처를 포함한다. 캐시 값에는 갱신 시각, 변경 결과에는 대상 환경, 목록에는 남은 결과의 존재가 필요할 수 있다.

모든 결과에 모든 메타데이터를 붙이지 않는다. 결과를 해석하거나 사용하는 방식을 바꾸는 정보를 제공한다.

## 관련된 다음 행동을 제공한다

오류는 복구 안내를 담을 수 있다. 성공 결과도 유용한 후속 행동을 제공할 수 있다. 생성한 객체 조회, 다음 페이지 읽기, 작업 확인, 변경 검증, 아직 취소 가능한 작업의 취소 등이 해당한다.

제작자가 관계를 정의한다. CLI는 실제 식별자를 넣고 알려진 상태에 맞춰 행동을 추린다. 사용자의 계획을 추론할 필요는 없다.

설명을 위한 응답은 다음과 같은 의미를 전달할 수 있다.

```text
결과: job-42 접수됨. 작업은 아직 완료되지 않음.
행동:
  상태 확인 -> tool job status job-42
  결과 조회 -> tool job result job-42
  취소      -> tool job cancel job-42
힌트: 결과는 작업 완료 후 읽을 수 있다.
```

이는 의미의 예시이며 고정된 전송 형식이 아니다. 행동에는 설명과 완성된 호출 인자를 제공한다. 호출자의 추가 입력이 실제로 필요할 때만 인자 템플릿을 사용하고 무엇을 채워야 하는지 알린다. 명령으로 표현할 수 없는 안내에는 짧은 힌트가 유용하다.

현재 결과와 직접 관련된 행동만 제공한다. 유용한 것이 없으면 생략한다. 전체 명령 목록을 덤프하거나 하나의 작업 순서를 보편적으로 강제하지 않는다.

## 영향을 설명하되 권한을 부여하지 않는다

조회와 상태 변경을 구분할 수 있게 한다. 필요한 경우 되돌릴 수 있는지, 반복 실행은 어떻게 동작하는지 설명한다. 정보가 없으면 알 수 없는 것으로 다룬다. 읽기 전용이거나 안전하다는 근거로 삼지 않는다.

후속 행동에도 같은 정보를 제공한다. 제안된 명령은 실행 허가가 아니다. 호출하는 에이전트는 여전히 사용자의 목적과 권한을 따라야 한다.

## 필수 사전 검사 없이 진단한다

도구에 유용한 준비 상태 검사가 있다면 선택적인 `doctor` 명령으로 제공할 수 있다. 제작자가 도구에 맞는 검사 항목을 선언한다. 보고서는 문제와 해결 행동을 알려주며, 직접 수정을 수행해서는 안 된다. 수정은 별도의 명시적 행동으로 제공한다.

매 작업 전에 doctor를 실행할 필요는 없다. 실행 명령은 이전 진단에 의존하지 않고 충족되지 않은 실행 조건을 명확히 처리해야 한다. 방금 성공한 검사도 조건이 그대로 유지된다고 보장하지는 않는다.

## 반복 실행의 의미를 알린다

응답을 받지 못했다고 명령이 실행되지 않은 것은 아니다. 반복 실행이 안전한지 설명한다. 중복이 문제가 되는 경우 도구에 맞는 결과 조회·요청 식별자·중복 방지 장치를 제공한다.

모든 명령에 이런 장치가 필요한 것은 아니다. 조회나 결정적인 변환은 이미 반복해도 안전할 수 있다. 응답이 유실됐다는 이유만으로 성공 여부가 불확실한 변경을 자동 재시도하지 않는다.
