# 7. 조건에 따라 필요한 패턴

공통 계약이 동일한 내부 장치를 뜻하지는 않는다. 도구가 실제로 소유한 상태와 의존성에 맞춰 기능을 선택한다.

## 설정과 지속 상태가 있는 도구

도구가 소유한 설정과 상태의 위치를 교체할 수 있게 한다. 홈 디렉터리는 설정·상태·캐시·자격 증명·로그를 묶는 한 방법이다. 어떤 자원을 포함하는지 문서화한다.

테스트 홈을 선택했을 때 실제 사용자 설정이나 저장소로 몰래 되돌아가지 않는다. 사용자가 명시한 작업 대상은 구분한다. 출력 파일을 고르는 것과 도구 자체의 홈을 고르는 것은 다르다.

상태 없는 변환에는 홈이 전혀 필요 없을 수 있다. 상태가 OS 자격 증명 저장소나 외부 서비스에도 있다면 디렉터리 교체만으로 충분하지 않다. 해당 의존성에도 적절한 테스트 경계를 제공한다.

## 네트워크와 인증

외부 접근은 교체 가능한 경계 뒤에 둔다. 테스트에서 다른 접속 대상이나 클라이언트를 선택할 수 있다. 임시 홈은 실제 네트워크 통신을 막지 않는다.

연결 문제·인증 상태·거절된 요청을 구분할 수 있게 알린다. 사람이 필요한 절차라면 무엇이 필요하고 어떻게 진행하는지 설명한다. 인증 프로토콜과 자격 증명 저장은 서비스와 환경에 맞춰 선택한다. 특정 프로토콜이나 토큰 출력 기능은 보편 요구가 아니다.

타임아웃과 재시도는 작업의 영향을 고려해야 한다. 변경 요청의 응답이 유실됐다고 재시도가 무해하다는 근거가 되지는 않는다. [5장](05-state-and-actions.md)의 반복 실행 계약을 사용한다.

## 장시간 작업과 스트림

장시간 작업은 상태·대기·결과·취소를 제공할 수 있다. 프레임워크는 모든 명령에 데몬이나 작업 데이터베이스를 요구하지 않으면서 선택적인 공통 계약을 제공할 수 있다. 필요에 따라 접수·진행·완료·실패 상태를 설명하고, 취소는 지원할 때만 노출한다.

스트림은 완성된 값이 아니다. 바이트를 쓴 뒤의 실패는 이미 나간 내용을 되돌릴 수 없다. 완료·실패 신호를 설명하고, 오류는 stdout payload와 분리하며, 부분 출력의 상태를 정직하게 알린다. 알려진 작업의 대기는 예상하지 못한 입력 질문과 다르다.

파이프로 여러 명령을 연결해도 전체 작업이 하나의 트랜잭션이 되지는 않는다. 일부 출력이나 변경이 이미 발생했을 수 있다. 입력의 완전성, 중간 실패, 취소 이후 남는 상태를 해당 작업의 계약에 맞게 설명한다. [4장](04-results-and-presentation.md#조합할-수-있는-출력)을 참고한다.

## 공유 자원

여러 호출자가 같은 자원을 사용하면 대상을 명시하고 동시 접근을 고려한다. 식별자는 바뀌는 UI 포커스나 추측한 목록 위치가 아닌 의도한 객체를 가리켜야 한다.

잠금·큐·데몬·소유권 기록은 가능한 기법이다. 모든 AI 도구에 장수 프로세스가 필요해서가 아니라 자원의 요구에 따라 선택한다. 어떤 방법이든 관련 상태를 노출하고 테스트에서 격리하거나 통제할 방법을 제공한다.

## 배포와 업데이트

사용자와 플랫폼에 맞는 배포·업데이트 방식을 선택한다. 실행 버전을 노출하고 사용 지식을 맞춘다. 패키지 매니저와 자체 업데이트가 다른 방식이 소유한 자원을 예상 밖으로 덮어쓰지 않게 한다.

독립 업데이트에는 다운로드 검증·원자적 교체·중단 후 복구가 필요할 수 있다. 이는 자체 업데이트를 하는 도구의 구현 관심사이며 모든 CLI 프레임워크의 요구는 아니다. 이 가이드는 패키지 매니저나 단일 바이너리 형식을 지정하지 않는다.
