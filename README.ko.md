# CLI for agents

**AI 에이전트를 위한 CLI는 어떤 모습이어야 할까?**

CLI는 에이전트가 도구를 실행하는 가장 익숙한 방법이다. 처음 접하는 도구도 도움말을 따라 필요한 명령을 찾고, 입력을 전달하고, 결과를 다음 작업에 연결할 수 있다. 셸을 사용할 수 있는 환경이라면 기존 CLI를 별도의 MCP 인터페이스로 감싸지 않고 활용할 수 있고, 여러 단계의 작업도 명령을 조합해 한 번에 실행할 수 있다.

이런 AI 에이전트 친화적인 CLI를 만드는 것은 사람을 위한 CLI와 설계의 초점이 조금 다르다. 도구를 선택할 때는 기능과 적용 상황을, 명령을 호출할 때는 입력과 사용 방법을, 결과를 받았을 때는 처리 상태와 가능한 다음 행동을 제공한다. 사용법을 미리 모두 전달하기보다, **실행 흐름에서 필요한 시점에 필요한 맥락이 들어오도록** 설계하는 것이다.

필요한 맥락이 들어오는 시점은 에이전트가 어디에 어텐션을 쓰는지에 영향을 준다. 도구의 모든 사용법을 처음부터 컨텍스트에 넣고 계속 기억하게 하기보다, 현재 명령과 실행 결과에 맞는 정보를 그때 제공한다. 결과에 실제 식별자가 채워진 후속 명령이 있다면 이전 설명을 찾아 호출을 다시 구성할 필요가 줄어든다. 파이프와 명령 조합은 판단이 필요 없는 중간 데이터를 다음 프로그램으로 바로 전달한다.

이 가이드는 그 흐름을 만드는 CLI 설계를 다룬다. 도움말과 사용 스킬을 통한 발견, 좋은 기본값과 명확한 입력 계약, 결과 해석과 후속 행동, 파이프를 통한 명령 조합을 설명한다. 이와 함께 명령 선언과 사용 지식을 연결하고 검증해, 도구가 설명하는 내용과 실제 동작을 일관되게 유지하는 제작 구조를 살펴본다.

### 발견과 사용 지식

도구 이름에서 시작해 필요한 명령과 사용 방법을 찾는다. 도움말은 문법을, 스킬은 작업 흐름을 설명한다. 기능이 많아져도 필요한 부분부터 읽을 수 있도록 구성한다.

### 입력과 실행

흔한 작업을 간단하게 만드는 기본값, 수정할 근거를 제공하는 입력 오류, 파일·stdin을 통한 복잡한 입력을 다룬다. 새로운 판단이 필요 없는 단계는 파이프나 명령 조합으로 한 번에 실행할 수 있게 한다.

### 결과와 다음 행동

JSON과 사람용 표현, 출력량과 페이지 조회, 부분 실패와 비동기 작업의 상태를 설명한다. 결과에 관련된 후속 명령을 제공하되, 조회한 외부 콘텐츠와 도구가 작성한 안내를 구분한다.

### 제작과 검증

명령 선언에서 도움말과 검증을 생성하고, 기능 가까이에 둔 사용 지식을 작업별 가이드로 조립한다. 결정 로직과 부수효과를 나누고, 함수부터 실제 CLI 호출까지 검증하는 구조를 살펴본다.

## 적용 범위

언어와 프레임워크에 독립적인 가이드다. 특정 패키지를 설치하지 않아도 원칙을 적용할 수 있다.

홈 디렉터리·네트워크·인증·장시간 작업은 해당 기능이 필요한 도구의 패턴으로 다룬다. 문서의 명령과 응답은 설계 예시이며, 정확한 명령 이름이나 필드명을 공통 규격으로 정하지 않는다.

영문이 기준이며 한국어판은 같은 내용을 다룬다.
