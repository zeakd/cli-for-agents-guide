# CLI for agents

**AI 에이전트를 위한 CLI는 어떤 모습이어야 할까?**

CLI는 에이전트에게 도구를 실행할 방법을 제공한다. 하지만 실행할 수 있다는 것만으로, 도구를 잘 사용하는 데 필요한 정보가 갖춰지는 것은 아니다.

명령 문법은 있어도 언제 사용하는지는 외부 문서를 찾아야 하고, 잘못된 옵션이 무시되기도 한다. 결과를 받아도 작업이 끝났는지, 어디까지 처리됐는지, 무엇을 이어서 할 수 있는지 불분명할 수 있다. 그 빈자리를 호출자의 탐색과 추측이 채운다.

이 가이드는 **발견하고, 호출하고, 결과를 해석하고, 다음 행동을 선택하는 과정**을 CLI의 설계 범위로 다룬다. 그리고 그 표면을 일관되게 만들고 유지하는 구조를 설명한다.

### 사용 지식을 발견한다

도구 이름만 입력해 시작하는 법을 찾고, 도움말에서 사용 스킬로 이어진다. 명령의 문법과 함께 언제 유용한지, 어떻게 조합하는지, 무엇을 주의해야 하는지 읽을 수 있다. 필요한 내용을 먼저 발견하고 상세 정보는 선택해서 읽는다.

### 올바르게 호출한다

흔한 사용에 반복적인 지시나 옵션이 필요하지 않도록 기본값을 설계한다. 입력 계약을 드러내고, 잘못된 요청에는 수정할 근거를 제공한다. 일반 결과의 JSON 기본 출력과 명시적인 사람용 표현, 예상 밖의 질문에서 멈추지 않는 실행을 다룬다.

### 결과에서 다음 판단으로 이어간다

접수와 완료, 일부와 전체를 구분하고 결과를 해석하는 데 필요한 상태와 범위를 알린다. 관련된 후속 명령과 힌트를 제공하되, 다음 행동의 선택은 호출자에게 남긴다. 정보가 많다면 필요한 만큼 보여주고 더 읽는 경로를 제공한다.

### 설명과 동작을 함께 유지한다

같은 선언에서 도움말과 검증을 만들고, 결정 로직과 부수효과를 나누며, 함수와 실제 CLI를 각각 테스트한다. 호출하는 에이전트뿐 아니라 코드를 만들고 유지하는 에이전트가 누락과 불일치를 줄이도록 돕는다.

## 적용 범위

언어와 프레임워크에 독립적인 설계 가이드다. 특정 패키지를 설치하지 않아도 원칙을 적용할 수 있다.

공통 계약과 조건별 패턴을 구분한다. 홈 디렉터리·네트워크·인증·장시간 작업은 해당 기능이 필요한 도구에 맞춰 다룬다. 모든 CLI에 같은 내부 구조를 요구하지 않는다.

8개 장으로 구성되며 영문이 기준이다. 한국어판은 같은 내용을 다룬다. 문서의 `tool ...` 호출은 설계 예시이며 특정 패키지에서 실행하는 예제가 아니다.
